## Project

**Business Rule AI Agent** — a ServiceNow Fluent application (scope: `x_1896745_test`, SDK v4.7.2) that uses ServiceNow's AI Agent platform (`sn_aia_agent`) to convert plain-English business requirements into syntactically correct, platform-safe Business Rule records on the `sys_script` table.

The AI Agent orchestrates: requirement parsing → execution timing selection → conflict detection → script generation → record insertion, while enforcing all platform safety rules (no recursive loops, no `current.update()` in Before rules, condition-builder-first approach).

## AI Agent Architecture (this project)

The agent uses a **single AiAgent** with multiple Script tools (not an AiAgenticWorkflow), because all tasks operate on the same capability type — reading platform configuration and writing to `sys_script`.

**Tool sequence inside the agent:**
1. **Parse Requirement** (script tool) — extracts trigger event, condition filter, and action from NL
2. **Detect Conflicts** (script tool → `conflict-detector` Script Include) — sweeps `sys_script`, Flow Designer (`sys_hub_flow`), UI Policies, Data Policies, Client Scripts for overlaps
3. **Validate Timing** (script tool → `business-rule-validator` Script Include) — enforces Before/After/Async selection rules
4. **Generate Script** (script tool) — produces syntactically correct JS handler with exception logging
5. **Create Business Rule** (CRUD `create` tool) — inserts record into `sys_script`

## Safety Rules (enforced in code, not just docs)

These are non-negotiable constraints that must be validated in `business-rule-validator.ts`:

- **Never allow** `current.update()` inside `before` or `after` rule scripts — causes recursive execution loops
- **Never generate** `query` action subscriptions without explicit user confirmation — fires on every table query
- **Always prefer** `filterCondition` over guard clauses in script body
- **Always redirect** After-rule same-record modifications to Before rules with a platform risk warning
- **Always include** try/catch with `gs.error()` logging in generated scripts
- **Never use** `GlideRecord` — always `GlideRecordSecure` in server scripts
- **Async only** for third-party integrations or operations that must not block UI thread

## Key Notes

- `now.config.json` holds scope identity. Instance credentials live in `.now-sdk/` (gitignored).
- `src/fluent/generated/keys.ts` is auto-generated by `npm run build` — commit it, never hand-edit.
- After `npm run transform` on XML files, delete the originals — XML wins over Fluent on build conflicts.
- `securityAcl` is **mandatory** on every `AiAgent` — the build will fail without it.
- `versionDetails` (not `versions`) is the correct property name on `AiAgent`.
- Tool `inputs` for `crud` tools is an **object** (`ToolInputType`); for `script` tools it is an **array**.
- The generated Business Rule's `script` must be a self-contained IIFE; `current` and `previous` are available as globals — no function wrapper needed.
