# Style Guide

Coding conventions for the Business Rule AI Agent project (ServiceNow Fluent SDK v4.7.2).

---

## File Naming

| Type | Convention | Example |
|---|---|---|
| Fluent artifact | `kebab-case.now.ts` | `business-rule-agent.now.ts` |
| Server module | `kebab-case.ts` | `conflict-detector.ts` |
| Directory | `kebab-case/` | `script-includes/` |

Never use PascalCase or camelCase for file or directory names.

---

## Directory Layout

Organize by artifact type. Each artifact type gets its own subdirectory:

```
src/fluent/
  ai-agents/          ← AiAgent / AiAgenticWorkflow definitions
  script-includes/    ← ScriptInclude definitions
  business-rules/     ← BusinessRule definitions (if any static rules needed)
  generated/          ← auto-generated by SDK, never edit manually

src/server/
  ai-agents/          ← script bodies referenced by AiAgent tool scripts
  script-includes/    ← logic for Script Includes (conflict detector, validator)
```

---

## Fluent File Conventions

Every `.now.ts` file follows this structure:

```typescript
import '@servicenow/sdk/global'
import { ArtifactType } from '@servicenow/sdk/core'
import { myFunction } from '../../server/subdirectory/my-module'

export const myArtifact = ArtifactType({
  $id: Now.ID['kebab-case-key'],
  name: 'Human Readable Name',
  // ...
})
```

Rules:
- Always import `@servicenow/sdk/global` first in files that use `Now.ID`
- Always use `Now.ID['kebab-case-key']` for `$id` — never hardcode sys_ids
- Export every top-level artifact (`export const`) so it can be re-exported from `index.now.ts`
- Import server logic as named function imports — never inline scripts as strings

---

## Server Module Conventions

Server modules live in `src/server/` and export named functions:

```typescript
import { gs, GlideRecord } from '@servicenow/glide'

export function myFunction(current: GlideRecord<'table_name'>, previous: GlideRecord<'table_name'>): void {
  try {
    // logic here
  } catch (e) {
    gs.error('x_1896745_test.myFunction: ' + e)
  }
}
```

Rules:
- Always type `current` and `previous` with the specific table generic: `GlideRecord<'incident'>`
- Always wrap logic in try/catch; log with `gs.error('scope.functionName: ' + e)`
- Never use `GlideRecord` — always use `GlideRecordSecure`
- Never call `current.update()` inside scripts used by `before` or `after` Business Rules
- Use `gs.addErrorMessage()` + `current.setAbortAction(true)` for validation failures in `before` rules
- Return values from script tool functions are serialized to string by the AI Agent platform — keep return shapes flat

## AI Agent Tool Conventions

### Script tools (`type: 'script'`)

- `inputs` is an **array** of `{ name, description, mandatory, value? }`
- `script` references a function from `src/server/`
- Always set `executionMode: 'autopilot'` for non-interactive pipeline steps
- Always set `preMessage` and `postMessage`

```typescript
{
  type: 'script',
  name: 'Tool Name',
  description: 'What this tool does.',
  active: true,
  executionMode: 'autopilot',
  preMessage: 'Running...',
  postMessage: 'Done.',
  inputs: [
    { name: 'param_name', description: 'What this param is', mandatory: true }
  ],
  script: myServerFunction,
}
```

### CRUD tools (`type: 'crud'`)

- `inputs` is an **object** (`ToolInputType`) with `operationName`, `table`, `inputFields`, etc.
- Use `number={{field_name}}^ORsys_id={{field_name}}` pattern for lookup by identifier
- Always specify `returnFields` for `lookup` operations

## Naming Keys

`Now.ID` keys must be globally unique within the scope. Use a descriptive, hyphenated name that encodes the artifact type:

| Artifact | Key Pattern | Example |
|---|---|---|
| AI Agent | `{name}-agent` | `business-rule-agent` |
| Agent ACL | `{name}-agent-acl` | `business-rule-agent-acl` |
| Script Include | `{name}-si` | `conflict-detector-si` |
| Business Rule | `{name}-br` | `validate-state-br` |

---

## Script Include Conventions

Script Includes in this project use `Class.create()` pattern (required for `sandboxCallable` or `clientCallable` includes). Logic files in `src/server/script-includes/` wrap standalone functions that are then invoked from the class body via `Now.include()`.

```typescript
// src/fluent/script-includes/conflict-detector.now.ts
import '@servicenow/sdk/global'
import { ScriptInclude } from '@servicenow/sdk/core'

ScriptInclude({
  $id: Now.ID['conflict-detector-si'],
  name: 'ConflictDetector',
  description: 'Sweeps platform configuration tables for conflicts before Business Rule creation.',
  accessibleFrom: 'package_private',
  script: Now.include('./conflict-detector.js'),  // class file, not module
})
```

For Script Includes, server-side files are `.js` class files (not `.ts` modules), because `ScriptInclude.script` is string-only and does not support module imports.

## Error Handling Pattern

All server-side functions must use this pattern:

```typescript
export function doSomething(inputs: Record<string, string>) {
  try {
    // ... logic
    return { success: true, result: value }
  } catch (e) {
    gs.error('x_1896745_test.doSomething: ' + String(e))
    return { success: false, error: String(e) }
  }
}
```

AI Agent script tools receive all inputs as **strings** at runtime. Parse numeric values explicitly:
```typescript
const count = parseInt(inputs.count, 10)
```

## Comments

Write comments only when the **why** is non-obvious. Do not comment what the code does — name it clearly instead.

Good:
```typescript
// filterCondition prevents this rule from firing on system queries (action: query fires on every GR.query())
filterCondition: 'active=true',
```

Bad:
```typescript
// Set the active flag to true
active: true,
```

---

## Business Rule Safety Checklist

Before deploying any Business Rule (generated or static):

- [ ] `before` rule: no `current.update()` call anywhere in the script
- [ ] `after` rule: no field modifications on `current` (use separate GR update if needed)
- [ ] `query` action: only used if explicitly required and confirmed
- [ ] `filterCondition` set: don't rely solely on script-body guard clauses
- [ ] try/catch with `gs.error()` present in script body
- [ ] `GlideRecordSecure` used (not `GlideRecord`) in any embedded queries
